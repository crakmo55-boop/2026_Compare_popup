## 4. "같은 문제가 반복된" 이유

이전 수정은 증상 단위였습니다.
- 이름 매칭: 영문 이름 정규화만 계속 보강했지만, 근본 원인은 **옵션명이 현지어**라는 것. 이름 비교로는 해결할 수 없는 구조였음.
- 순번 클릭: 클릭 표시를 다시 붙이는 식으로 보완했지만, 목록이 다시 그려지거나 재정렬되면 순번 자체가 틀어짐.
- 첫 번째 루트 읽기, 사업부 단위 예외 처리, Set 사이 Compare 선택 상태 공유는 한 번도 점검되지 않았음.

## 5. 조치 (코드 변경)

### 5.1 Key spec 대체 규칙 (사용자 지시) — `common/substitute.py`, Popup·Landing 공통
"요청 제품에 Key spec이 없으면 매핑에서 다른 제품을 골라 **그 사업부에 한하여** 다시 확인"
- 후보: 같은 사업부·같은 Set 카테고리의 매핑 대체 후보 (같은 사업부 다른 Set에서 쓴 제품 제외)
- 열 값 없음 → 그 제품만 교체
- 섹션 전체 미노출 / 새 팝업 미표시 / Compare 버튼 미반영 → 원인 제품을 모르므로 **한 번에 한 제품씩** 바꿔 보고, 해결되면 그 제품을 원인으로 확정. 하나씩 바꿔도 안 되면 Set 전체 교체(최대 2회)
- 후보로도 해결되지 않으면 **원래 제품으로 되돌려 다시 확인한 결과를 기록**하여 결함 후보가 결과에서 사라지지 않게 함
- 판정 규칙(섹션 미노출 = Popup 확인 필요 / Landing FAIL 등)은 그대로
- 비고 `[Key spec 대체] 원래 제품 X (이름) 사유 → 이 제품으로 대체`, 로그 `[KEYSPEC-대체]`, 실행 끝 `[DONE] Key spec 대체 N행` 목록
- 한도: Set당 6회, Popup·Landing Set당 300초 (`common/config.py`)

### 5.2 Popup
- 화면에 보이는 팝업 루트만 읽음 (D 해결)
- PF 대체 후보를 "체크박스 바로 있음 → 옵션 전환 필요(카드에 체크박스 있음) → 카드에 체크박스 없음" 순서로 시도. 체크박스 있는 후보는 시도 한도와 무관 (E 해결)
- `--no-data` 판단: 체크박스 또는 카드 Compare 영역이 그려질 때까지 기다린 뒤 판단, 문구 통일 "사이트 PF 카드에 Compare 기능 없음" (A 시간·문구)
- 새 팝업 미표시 / 버튼 미반영: PF를 새로 열어 같은 제품으로 1회 재확인 → 그래도 안 되면 대체 규칙 (B)
- Compare 버튼 클릭을 실제 클릭으로(실패 시 DOM click). 버튼이 준비 안 되면 15초 + 실제 체크 클릭 10초 후 버튼 SKU·체크 상태·화면 메시지를 비고에 기록 (F)
- 팝업 닫기는 기존 코드와 같은 X 버튼(`#pdd43MasterCompare button.layer-popup__close`)
- Compare API 응답이 10초 동안 하나도 없으면 30초를 다 기다리지 않음

### 5.3 Landing
- **Popup 결과의 화면 표시명(현지어)을 1순위 단서로 사용**. 11:28 Popup과 13:07 Landing 모두 PASS인 691개 SKU 중 634개(92%)가 표시명이 완전히 같았음. Landing 실패 행의 원래 제품 대부분이 Popup에 표시명이 있었음
- 이름으로 못 찾으면 **옵션을 직접 골라 열 SKU를 읽어 확인** (Set당 25개까지, 확인한 옵션→SKU는 같은 페이지에서 재사용)
- 클릭: 드롭다운을 연 뒤 **보이는 옵션을 글자로 그 자리에서 찾아** 누름. 이미 선택된 옵션은 누르지 않음, 다시 그려져 사라지면 다시 찾아 1회 재시도 (B-③④)
- 같은 이름 옵션 수 제한 없음, 열 75초·Set 300초 한도 (ES·AL 시간)
- 이미 어떤 열에 떠 있는 제품은 그 열에 둠 (불필요한 선택·열 충돌 방지)
- 못 띄운 열: SKU 매칭도 `확인 필요` (사이트 SKU 불일치 FAIL과 구분)
- 페이지 이동 대응: 모든 스크립트 호출을 로드 대기 후 재실행(`ev`/`wf`), 페이지 로드 뒤 네트워크 안정 대기 (A)
